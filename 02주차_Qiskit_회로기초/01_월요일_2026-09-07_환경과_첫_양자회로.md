## 35~60분: QuantumCircuit의 구조

```python
from qiskit import QuantumCircuit

circuit = QuantumCircuit(2, 2, name="first_circuit")
circuit.h(0)
circuit.cx(0, 1)
circuit.measure([0, 1], [0, 1])

print(circuit.draw(output="text"))
```

`QuantumCircuit(2, 2)`에서 첫 번째 2는 quantum bit 수, 두 번째 2는 classical bit 수입니다. 게이트는 위에서 아래가 아니라 시간축상 왼쪽에서 오른쪽으로 적용됩니다.

회로의 층:

1. quantum wires: 아직 측정되지 않은 상태가 변화하는 선
2. classical wires: 측정 결과를 저장하는 고전 비트
3. instruction: gate, measure, reset, barrier 등
4. register: 여러 bit를 이름 있는 묶음으로 관리하는 구조

측정이 필요 없는 상태 계산에서는 classical bit를 처음부터 만들 필요가 없습니다.

```python
state_circuit = QuantumCircuit(2)
state_circuit.h(0)
state_circuit.cx(0, 1)
```

## 60~70분: 회로 속성

```python
print("qubits:", circuit.num_qubits)
print("clbits:", circuit.num_clbits)
print("width:", circuit.width())
print("size:", circuit.size())
print("depth:", circuit.depth())
print("operations:", circuit.count_ops())
```

- `width`: quantum bit와 classical bit를 포함한 회로의 폭
- `size`: instruction 개수. barrier 포함 여부 같은 옵션은 버전 문서를 확인
- `depth`: 서로 겹쳐 병렬 수행할 수 없는 instruction layer 수
- `count_ops`: instruction 이름별 개수

`코드 줄 수`, `gate 수`, `depth`는 서로 다릅니다. 서로 다른 qubit에 적용되는 두 gate는 코드로 두 줄이어도 같은 depth layer에 놓일 수 있습니다.

### 예측 문제

```python
parallel = QuantumCircuit(2)
parallel.h(0)
parallel.x(1)
```

두 instruction의 size는 2지만 이상적인 회로 depth는 1입니다.

## 70~95분: 상태 계산과 실행을 분리하기

측정 전 순수 상태를 알고 싶다면 다음처럼 계산합니다.

```python
from qiskit.quantum_info import Statevector

state = Statevector.from_instruction(state_circuit)
print(state.draw("text"))
print(state.probabilities_dict())
```

이것은 샷 기반 실행이 아닙니다. 회로의 이상적인 순수 상태를 직접 계산합니다.

샷 결과가 필요하면 측정이 있는 회로와 Sampler를 사용합니다.

```python
from qiskit.primitives import StatevectorSampler

sampler = StatevectorSampler(default_shots=1000, seed=17)
result = sampler.run([circuit]).result()
counts = result[0].data.c.get_counts()
print(counts)
```

여기서 `c`는 회로의 classical register 이름입니다. `measure_all()`이 만든 register라면 흔히 `meas`입니다. 결과 객체를 외워서 추측하지 말고 `result[0].data` 구조를 확인합니다.

### 수학·논리 전개

2큐비트 회로의 초기 상태는 00이고 H를 q0에 적용하면 (00+01)/sqrt(2), 이어서 CX(q0,q1)를 적용하면 (00+11)/sqrt(2)가 됩니다. 여기까지는 유니터리 상태 계산이며 measure 명령과 Sampler의 유한 샷 표본은 별도 단계입니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

### 손으로 따라가는 예제

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 설치 버전이 다르거나 classical register 이름을 잘못 가정하면 개념이 맞아도 import 또는 결과 접근 단계에서 실패합니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
