## 왜 비트 순서가 중요한가

Bell 상태는 `00`과 `11`처럼 대칭이라 순서를 뒤집어도 오류가 드러나지 않습니다. `q0=1, q1=0` 같은 비대칭 상태를 사용해야 해석을 검증할 수 있습니다.

Qiskit의 대표 관례:

- qubit index는 `q0`, `q1`, ... 순서
- statevector basis index에서 `q0`가 least significant bit로 작동
- classical bitstring은 보통 높은 index가 왼쪽, `c0`가 오른쪽
- 여러 classical register가 있으면 표시 사이에 공백이 생길 수 있음

따라서 `q0=1, q1=0`을 각각 `c0`, `c1`에 측정하면 출력 문자열은 일반적으로 `01`입니다. 왼쪽은 `c1=0`, 오른쪽은 `c0=1`입니다.

## 명시적 register

```python
from qiskit import QuantumCircuit, QuantumRegister, ClassicalRegister

qreg = QuantumRegister(2, "q")
creg = ClassicalRegister(2, "c")
circuit = QuantumCircuit(qreg, creg)

circuit.x(qreg[0])
circuit.measure(qreg[0], creg[0])
circuit.measure(qreg[1], creg[1])

print(circuit.draw("text"))
```

실행 전에 count key를 예상합니다.

## 매핑을 바꾼 실험

```python
swapped = QuantumCircuit(2, 2)
swapped.x(0)
swapped.measure(0, 1)
swapped.measure(1, 0)
```

quantum state는 같지만 classical mapping을 바꾸었으므로 count 문자열은 달라집니다. 측정 결과 해석은 gate 회로뿐 아니라 `qubit → clbit` 연결을 포함해야 합니다.

## measure_all의 주의점

```python
qc = QuantumCircuit(2)
qc.x(0)
qc.measure_all()
print(qc.cregs)
```

`measure_all()`은 필요하면 새 classical register를 추가합니다. 이미 classical bit가 있는 회로에서 사용하면 기대하지 않은 register가 추가될 수 있으므로 회로 구조를 확인합니다. `measure_all(inplace=False)` 같은 옵션은 설치 버전 서명을 확인합니다.

## 측정과 Statevector

측정 instruction을 포함한 회로는 단순한 유니터리 상태 준비 회로가 아닙니다. 다음 구조를 권장합니다.

```python
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

prep = QuantumCircuit(2)
prep.x(0)

state = Statevector.from_instruction(prep)

measured = prep.copy()
measured.measure_all()
```

`prep`은 상태 분석용, `measured`는 샷 실행용입니다.

## Sampler로 검증

```python
from qiskit.primitives import StatevectorSampler

sampler = StatevectorSampler(default_shots=100, seed=23)
result = sampler.run([measured]).result()
counts = result[0].data.meas.get_counts()
print(counts)
```

이상적 회로이므로 `01`이 100회 나와야 합니다. 여기서는 확률적 중첩이 없으므로 샷 변동도 없습니다.

## 2. 핵심 유도와 손계산

### 수학·논리 전개

measure(q0,c1)과 measure(q1,c0)를 사용하면 기록은 교차됩니다. counts 문자열은 보통 높은 인덱스 고전 비트에서 낮은 인덱스 순으로 보이므로 key의 왼쪽 문자는 c1, 오른쪽 문자는 c0라는 표를 먼저 만들어야 합니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

1. 출발하는 상태, 데이터, 변수 또는 가정을 먼저 씁니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 문자열을 q0q1이라고 단정하거나 여러 classical register 사이의 공백과 순서를 무시하면 올바른 결과도 반대로 읽습니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
