## 목표

- control·target 순서를 회로 그림과 코드에서 확인합니다.
- 선형성을 이용해 중첩 입력의 출력을 계산합니다.

## 회상

1. $H|0\rangle$과 $Z|+\rangle$은 무엇입니까?
2. $|+0\rangle$은 분리 가능한가요?
3. 2큐비트 statevector에서 가능한 basis label은 무엇입니까?

## CX

첫 qubit을 control, 둘째를 target으로 쓰는 교재 표기에서

$$
|00\rangle\to|00\rangle,
|01\rangle\to|01\rangle,
|10\rangle\to|11\rangle,
|11\rangle\to|10\rangle.
$$

중첩 입력에는 각 기저 성분에 선형적으로 적용합니다.

$$
CX\frac{|00\rangle+|10\rangle}{\sqrt2}
=\frac{|00\rangle+|11\rangle}{\sqrt2}.
$$

그러나 $CX|00\rangle=|00\rangle$이므로 CX가 항상 얽힘을 만드는 것은 아닙니다. 입력 상태와 gate의 조합이 중요합니다.

## CZ

CZ는 $|11\rangle$ 성분에만 -1 위상을 줍니다.

$$CZ=\operatorname{diag}(1,1,1,-1).$$

계산기저 입력의 bit 값은 바뀌지 않지만 중첩에서는 상대위상을 바꾸어 얽힘이나 간섭에 영향을 줍니다.

$$CZ=(I\otimes H)CX(I\otimes H)$$

이라는 관계는 target의 기저를 H로 바꾸면 controlled-X와 controlled-Z가 연결됨을 보여줍니다.

## SWAP

$$SWAP|a,b\rangle=|b,a\rangle.$$

SWAP은 일반적으로 세 개의 CX로 분해할 수 있습니다.

$$SWAP=CX_{01}CX_{10}CX_{01}.$$

교재 수식에서 행렬은 오른쪽부터 적용됨에 주의합니다.

## Qiskit 실습

```python
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

qc = QuantumCircuit(2)
qc.x(0)
qc.cx(0, 1)

print(qc.draw("text"))
print(Statevector.from_instruction(qc).probabilities_dict())
```

Qiskit 코드 `cx(control_qubit, target_qubit)`의 인자 순서를 회로 그림에서 다시 확인합니다.

### controlled gate 만들기

```python
from qiskit.circuit.library import RYGate

controlled_ry = RYGate(0.4).control(1)

qc = QuantumCircuit(2)
qc.append(controlled_ry, [0, 1])
print(qc.draw("text"))
```

`append`의 qubit 목록 순서는 생성한 gate 정의와 일치해야 합니다.

## 단계별 과제

1. $|01\rangle$, $|10\rangle$ 입력을 각각 준비하고 `cx(0,1)` 결과를 예측합니다.
2. `cx(1,0)`으로 control·target을 바꾸어 차이를 비교합니다.
3. `swap(0,1)`과 세 CX 분해가 같은지 `Operator.equiv`로 확인합니다.
4. $|++\rangle$에 CZ를 적용한 상태가 분리 가능한지 계수 determinant로 판정합니다.

```python
from qiskit.quantum_info import Operator

print(Operator(swap_direct).equiv(Operator(swap_decomposed)))
```

## 2. 핵심 유도와 손계산

### 수학·논리 전개

CX(q0,q1)는 각 basis 성분에서 q0가 1일 때만 q1을 XOR 1로 바꿉니다. 입력 (00+01)/sqrt(2)는 q0가 중첩된 상태이므로 출력 (00+11)/sqrt(2)가 되고 이 계수 행렬은 두 단일 큐비트 벡터의 외적으로 분해되지 않습니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

### 실행 전에 적을 내용

- 틀린 접근: 대상 개념의 이름이나 코드 호출만 기억하면 의미도 안다고 생각합니다. 대상은 가역성과 측정입니다.
- 교정 근거: 다중 큐비트 게이트는 유니터리이므로 정보가 보존되지만 측정은 그 뒤의 상태와 고전 기록을 별도로 다뤄야 합니다.
- 확인 질문: 대상 개념 가역성과 측정에서 입력 조건 하나가 바뀌면 어떤 출력이 달라집니까?
- 최소 반례: 대상 개념 가역성과 측정에서 조건 하나를 깨뜨린 작은 예를 만듭니다.
- 복구 행동: 본문의 가역성과 측정 예제를 가장 작은 크기로 줄여 손계산과 다시 비교합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. Qiskit의 큐비트 인덱스와 상태벡터 basis 문자열 순서를 섞거나 control과 target을 뒤집으면 전혀 다른 연산을 검증하게 됩니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
