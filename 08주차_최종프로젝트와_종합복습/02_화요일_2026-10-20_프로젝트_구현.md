## 권장 노트북 구조

### 0. 환경

- Python·Qiskit·SciPy version
- random seed
- 실제 QPU 제출 없음/있음 명시

### 1. 문제 데이터

graph 또는 QUBO 계수를 한 곳에 정의합니다. 뒤 셀에서 숫자를 중복 hard-code하지 않습니다.

### 2. 순수 고전 함수

```python
def objective(bits: tuple[int, ...]) -> float:
    ...
```

Qiskit이 없어도 테스트 가능해야 합니다.

### 3. brute force

모든 해와 objective를 table로 만들고 optimal set을 저장합니다.

### 4. Hamiltonian builder

```python
def build_cost_operator(problem) -> tuple[SparsePauliOp, float]:
    ...
```

operator와 offset을 함께 반환하여 누락을 줄입니다.

### 5. basis validation

모든 bitstring에서 assertion합니다. 이 단계가 실패하면 QAOA로 넘어가지 않습니다.

### 6. ansatz와 cost

ansatz parameter order를 출력하고 cost function input shape를 검증합니다.

### 7. optimization

seed별 result를 구조화된 list로 저장합니다. best run만 남기지 않습니다.

### 8. sampling·decode

count key를 original variable tuple로 바꾸는 함수를 독립 테스트합니다.

### 9. summary

classical optimum, expected energy, most likely bitstring, objective, approximation ratio, depth를 한 표로 표시합니다.

## implementation 원칙

- 함수는 notebook global variable을 암묵적으로 읽지 않게 합니다.
- 계산 함수와 plotting 함수를 분리합니다.
- output label에 단위를 씁니다.
- `assert` message에 bitstring·expected·actual을 포함합니다.
- dataframe은 표시용이며 진실의 원천을 여러 곳에 복제하지 않습니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 한 셀에 모델 생성, 실행, plotting을 섞거나 숨은 전역 상태를 사용하면 재실행 순서에 따라 결과가 달라집니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
