## 추천 프로젝트

기본 프로젝트는 weighted MaxCut입니다. 응용 맥락을 원하면 기존 자료의 농작물 배치 문제를 단순화한 4변수 QUBO로 바꿀 수 있습니다. 문제를 바꿔도 다음 조건을 만족해야 합니다.

- binary variable 3~6개
- brute-force 검증 가능
- quadratic objective
- feasible 해와 objective를 명확히 계산 가능
- QAOA 결과 bitstring을 원래 문제로 해석 가능

## 성공 기준 예

`QAOA가 정확한 최적해를 찾는다`만 쓰면 seed·shots·p에 따라 모호합니다. 다음처럼 측정 가능하게 씁니다.

- 모든 basis state에서 Hamiltonian expectation과 classical objective가 일치
- 최소 10개 initial seed 중 best run에서 optimal bitstring probability 0.5 이상
- top-3 sampled bitstring 안에 optimal solution 포함
- approximation ratio와 circuit depth를 함께 보고
- endian·sign 관련 unit test 100% 통과

숫자는 문제에 맞게 조정하며 결과를 보고 사후에 성공 기준을 낮추지 않습니다.

## architecture

```text
problem data
→ classical objective
→ brute-force baseline
→ QUBO coefficients
→ Ising SparsePauliOp + offset
→ basis-state validation
→ QAOAAnsatz
→ StatevectorEstimator cost
→ classical optimizer restarts
→ StatevectorSampler distribution
→ decoded solution
→ optional transpile/noise analysis
```

## 테스트 계획

1. objective unit tests: 알려진 bitstring 값
2. Hamiltonian tests: 전 basis expectation
3. circuit tests: parameter count, no unbound values after assign
4. distribution tests: count 합=shots, key 길이=n
5. decoder tests: Qiskit key→variable vector
6. regression tests: fixed seed baseline metrics

## 위험 목록

- maximize/minimize sign 반전
- Q matrix double counting
- constant offset 누락
- Pauli label endian
- sampler count endian
- parameter vector ordering
- optimizer local minimum
- p 증가로 transpiled depth 급증
- noise model을 실제 성능으로 과해석

## 2. 핵심 유도와 손계산

### 수학·논리 전개

프로젝트 범위는 시간 예산 안에서 질문, 독립 baseline, 양자 구현, 교차 검증, 결론까지 닫히는 최소 단위여야 합니다. 성공 기준은 실행 여부가 아니라 관찰 가능한 수치와 허용 오차로 표현합니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

1. 출발하는 상태, 데이터, 변수 또는 가정을 먼저 씁니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

오늘 가장 가능성 높은 실패는 다음과 같습니다. 주제를 넓게 잡거나 성공을 실행 완료로 정의하면 결과가 나와도 무엇을 배웠고 무엇이 맞는지 평가할 수 없습니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
