# 8주차 금요일 - 최종 평가와 다음 로드맵

## 목표

- 8주 동안 복구한 지식을 구두 설명·빈 화면 구현·프로젝트 발표로 입증합니다.
- 영역별 현재 수준을 근거와 함께 평가합니다.
- 다음 90일 동안 유지·심화할 한 가지 주력 경로를 선택합니다.

## 최종 평가 구성

### 1. 10분 구두 설명

다음 흐름을 화면 없이 설명합니다.

```text
큐비트 상태
→ 유니터리 gate
→ 다중 qubit·얽힘
→ 측정과 샷
→ Qiskit 회로
→ transpilation·backend target
→ Sampler/Estimator V2
→ QUBO·Ising·QAOA
```

각 화살표에서 `왜 다음 개념이 필요한가`를 말합니다.

### 2. 30분 빈 화면 구현

- Bell 회로와 상태 검증
- 비대칭 measurement bit order 확인
- StatevectorEstimator 기대값
- 작은 circuit의 transpilation 지표

### 3. 40분 프로젝트 발표

- 문제·baseline 5분
- Hamiltonian·검증 10분
- QAOA·optimizer 10분
- 결과·resource·noise 10분
- 한계·다음 실험 5분

### 4. 20분 회고

- 처음 진단과 현재 능력 비교
- 가장 많이 바뀐 오개념
- 가장 약한 영역
- 앞으로 유지할 반복 습관

## 다음 90일 로드맵 선택

### A. Qiskit v2 자격시험

- 공식 exam objective와 study guide 기준으로 gap 분석
- circuit·operation·run·Sampler·Estimator·visualization·result·OpenQASM 영역별 문제
- 제한시간 mock test
- 구형 C1000-112 문제는 현대화 후 기초 문제로만 사용

### B. 양자 알고리즘

- phase estimation
- QFT
- amplitude estimation
- Hamiltonian simulation
- variational eigensolver
- complexity와 oracle model

### C. 하드웨어·오류

- calibration·Target 분석
- randomized benchmarking 개념
- readout mitigation
- zero-noise extrapolation
- dynamical decoupling·twirling
- quantum error correction 기초

### D. 최적화·QML

- constrained QUBO modeling
- QAOA mixer 설계
- warm-start·parameter transfer
- variational landscape·barren plateau
- kernel·variational classifier를 고전 baseline과 비교

## 2. 핵심 유도와 손계산

### 수학·논리 전개

숙달 점수는 설명, 손계산, 빈 화면 구현, 오류 진단의 네 축으로 분리합니다. 주제 평균만 보면 한 축의 심각한 약점이 가려지므로 각 축의 증거와 최소 통과 기준을 따로 둡니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

1. 출발하는 상태, 데이터, 변수 또는 가정을 먼저 씁니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

### 손으로 따라가는 예제

Bell 또는 QAOA 파이프라인을 10분 설명하고 30분 안에 핵심 코드를 재구성합니다. 결과가 틀렸다면 오류 위치를 찾고 수정 근거까지 제시해야 디버깅 축을 통과합니다.

#### 예제 재현 절차

- 첫 번째 시도에서는 코드를 실행하지 않습니다.
- 입력과 가능한 출력 후보를 종이에 적습니다.
- 중간 상태 또는 중간 값을 최소 두 단계 기록합니다.
- 마지막에만 기존 본문의 코드와 비교합니다.
- 값이 다르면 정답을 고치기 전에 convention과 순서를 먼저 확인합니다.

평가표의 각 점수 옆에 파일, 코드 셀, 계산지, 설명 녹취 같은 증거 위치를 남깁니다. 다음 90일 계획은 가장 낮은 축과 원하는 전문 경로가 겹치는 한 가지 산출물로 시작합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 완강 자체를 숙달로 간주하거나 여러 진로를 동시에 시작하면 복습 간격과 프로젝트 완성도가 무너집니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
