# 4주차 화요일 - 매개변수화 회로

## 목표

- `Parameter`, `ParameterVector`로 회로 구조와 수치를 분리합니다.
- parameter 순서를 추측하지 않고 명시적으로 binding합니다.
- sweep 결과를 기대값 또는 확률 곡선으로 해석합니다.
- variational algorithm의 회로 재사용 구조를 이해합니다.

## Parameter

```python
import numpy as np
from qiskit import QuantumCircuit
from qiskit.circuit import Parameter

theta = Parameter("theta")
qc = QuantumCircuit(1)
qc.ry(theta, 0)
```

아직 수치가 없는 symbolic circuit입니다. `Statevector.from_instruction(qc)`를 바로 호출하면 unbound parameter 오류가 발생합니다.

```python
bound = qc.assign_parameters({theta: np.pi / 2}, inplace=False)
```

구형 `bind_parameters`가 아니라 현재 `assign_parameters`를 사용합니다.

## ParameterVector

```python
from qiskit.circuit import ParameterVector

params = ParameterVector("theta", 3)
ansatz = QuantumCircuit(3)
for qubit, parameter in enumerate(params):
    ansatz.ry(parameter, qubit)
```

`ansatz.parameters`의 정렬을 위치 기준으로 무조건 가정하지 않습니다. dictionary binding으로 의미를 명시하면 안전합니다.

## sweep

$$R_y(\theta)|0\rangle
=\cos(\theta/2)|0\rangle+sin(\theta/2)|1\rangle.$$

따라서 $P(1)=\sin^2(\theta/2)$입니다.

```python
from qiskit.quantum_info import Statevector

angles = np.linspace(0, 2 * np.pi, 9)
rows = []

for angle in angles:
    bound = qc.assign_parameters({theta: angle})
    p1 = Statevector.from_instruction(bound).probabilities()[1]
    rows.append((angle, p1))

for angle, p1 in rows:
    print(f"theta={angle:.3f}, P(1)={p1:.3f}")
```

## 회로 구조와 데이터 분리

같은 parameterized circuit에 여러 값만 바꾸는 방식은 variational algorithm과 Primitive PUB의 vectorized input으로 이어집니다. 회로를 매 반복마다 새로 만들기보다 구조와 parameter values를 분리합니다.

## 과제

1. Rx·Rz 두 parameter를 갖는 회로를 만들고 순서를 바꿨을 때 결과를 비교합니다.
2. $\theta=0,\pi/2,\pi,3\pi/2,2\pi$에서 $P(1)$을 손으로 예측합니다.
3. 2큐비트 `ry(theta[0]) → cx → ry(theta[1])` ansatz를 만듭니다.
4. 일부 parameter만 binding한 회로와 전부 binding한 회로의 차이를 확인합니다.

## 자주 하는 실수

- degree를 넣습니다.
- parameter 이름이 같은 서로 다른 객체를 동일하다고 가정합니다.
- parameter 목록 순서를 출력하지 않고 list binding합니다.
- `inplace` 여부를 확인하지 않아 원본이 바뀌었다고 오해합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

## 4. 예측 중심 통합 실험

### 실험 질문

Parameter와 ParameterVector로 회전 회로를 만든 뒤 여러 각도 값을 bind하고 Statevector 또는 Primitive PUB sweep 결과를 비교합니다.

### 실행 전에 적을 내용

1. 입력 상태 또는 입력 데이터의 크기와 순서를 적습니다.

2. 회로나 수식이 적용되는 순서를 한 단계씩 번호로 씁니다.

3. 정확히 예측할 수 있는 출력과 유한 샷 때문에 흔들릴 출력을 구분합니다.

4. 성공을 판정할 수치 또는 구조적 조건을 하나 정합니다.

5. 실패했을 때 가장 먼저 출력할 type, shape, mapping, version을 적습니다.

### 예상 결과

회로를 매번 다시 만들지 않아도 같은 구조에 값을 바꿀 수 있고 각도 0, pi/2, pi 같은 기준점은 손계산과 일치해야 합니다.

|---|---|---|---|
| 객체 type |  |  |  |
| 배열 또는 결과 shape |  |  |  |
| 가능한 basis·bitstring |  |  |  |
| 핵심 수치 |  |  |  |
| 회로 size·depth |  |  |  |
| mapping·register |  |  |  |

### 실행 후 비교 순서

1. 코드가 실행됐다는 사실과 결과가 맞다는 판단을 분리합니다.

2. 먼저 type과 shape가 예측과 같은지 확인합니다.

3. 다음으로 basis 순서, parameter 순서, register 이름을 확인합니다.

4. 정확한 이론값과 샷 기반 추정치를 같은 허용 오차로 비교하지 않습니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 매개변수 순서를 이름 추측으로 정하거나 일부만 바인딩한 회로를 실행하면 값 shape 오류 또는 남은 parameter 오류가 발생합니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
