## 구형 API 주의

구형 자료의 `qc.qasm()`은 제거되었습니다. 현재 OpenQASM 2는 `qiskit.qasm2` 모듈을 사용합니다.

```python
from qiskit import QuantumCircuit, qasm2

qc = QuantumCircuit(2, 2)
qc.h(0)
qc.cx(0, 1)
qc.measure([0, 1], [0, 1])

program = qasm2.dumps(qc)
print(program)
```

파일 입출력:

```python
qasm2.dump(qc, "bell.qasm")
loaded = qasm2.load("bell.qasm")
```

## OpenQASM의 역할

OpenQASM은 회로 프로그램 상호운용 언어입니다. Qiskit 객체의 Python metadata, 임의 annotation, 모든 control-flow·custom object를 완벽히 보존하는 일반 serialization 형식으로 보지 않습니다.

OpenQASM 2는 비교적 단순한 gate·register 언어이고 OpenQASM 3은 더 풍부한 classical control, timing·type system을 목표로 합니다. Qiskit의 QASM 3 import 기능은 optional dependency와 버전 조건이 있을 수 있으므로 설치된 버전의 공식 문서를 확인합니다.

## QPY

QPY는 Qiskit 회로를 versioned binary 형식으로 저장하기 위한 선택입니다.

```python
from qiskit import qpy

with open("bell.qpy", "wb") as stream:
    qpy.dump(qc, stream)

with open("bell.qpy", "rb") as stream:
    restored = qpy.load(stream)[0]
```

QPY도 무한한 미래 호환을 약속하는 일반 표준은 아니므로 지원 version 범위를 확인합니다.

## round-trip 검증

단순 문자열이 같다는 것보다 회로의 의미를 검증합니다.

- qubit·clbit 수
- instruction 순서와 parameter
- classical mapping
- measurement 없는 unitary 부분의 Operator 동등성
- 대표 입력에 대한 결과 분포
- metadata 보존 여부

## 과제

1. parameterized circuit을 QASM 2로 export할 수 있는 범위를 확인합니다.
2. custom gate가 export될 때 어떤 gate definition이 생기는지 관찰합니다.
3. QASM과 QPY round-trip 후 `draw`, `count_ops`, 결과를 비교합니다.
4. `OpenQASM이 회로를 저장하므로 pickle처럼 모든 객체를 보존한다`가 틀린 이유를 씁니다.

## 2. 핵심 유도와 손계산

### 수학·논리 전개

round-trip은 deserialize(serialize(circuit))를 원본과 비교하는 합성 검사입니다. 텍스트 문법이 표현하지 못하는 metadata나 사용자 객체는 함수 합성 뒤 복원되지 않으므로 동작 동등성과 구조 동일성을 분리해야 합니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

1. 출발하는 상태, 데이터, 변수 또는 가정을 먼저 씁니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

### 손으로 따라가는 예제

이름, parameter, metadata가 있는 작은 회로를 QASM 2와 QPY로 각각 왕복합니다. QASM 복원본은 지원 instruction의 동작을 유지해도 Python metadata가 사라질 수 있고 QPY는 Qiskit 구조를 더 많이 보존합니다.

#### 예제 재현 절차

- 첫 번째 시도에서는 코드를 실행하지 않습니다.
- 입력과 가능한 출력 후보를 종이에 적습니다.
- 중간 상태 또는 중간 값을 최소 두 단계 기록합니다.
- 마지막에만 기존 본문의 코드와 비교합니다.
- 값이 다르면 정답을 고치기 전에 convention과 순서를 먼저 확인합니다.

### 출력 해석 기준

파일이 생성되었다는 사실, 다시 로드되었다는 사실, 회로가 같은 동작을 한다는 사실, 객체 정보가 보존되었다는 사실을 네 개의 별도 검사로 기록합니다.

오늘 가장 가능성 높은 실패는 다음과 같습니다. 구형 circuit.qasm 메서드를 사용하거나 파일을 읽었다는 사실만으로 동등성을 가정하면 손실된 정보와 버전 호환 문제를 놓칩니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
