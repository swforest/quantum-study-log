## QUBO

QUBO는 일반적으로

$$
f(x)=x^TQx+c,
\qquad x_i\in\{0,1\}
$$

를 최소화 또는 최대화합니다. binary 성질 때문에 $x_i^2=x_i$이므로 선형항을 diagonal에 넣을 수 있습니다.

### convention 주의

$Q$를 대칭행렬로 쓰면

$$x^TQx=\sum_iQ_{ii}x_i+2\sum_{i<j}Q_{ij}x_ix_j$$

입니다. 어떤 라이브러리는 upper triangular coefficient를 한 번만 합산합니다. 같은 숫자 행렬도 convention에 따라 목적함수가 달라질 수 있으므로 손계산으로 한 bitstring을 검증합니다.

## 예제: 3-node MaxCut

triangle graph의 각 edge weight가 1이고 $x_i$가 partition을 나타내면 cut 값은

$$
C(x)=\sum_{(i,j)\in E}(x_i+x_j-2x_ix_j).
$$

$x_i\ne x_j$이면 edge contribution이 1, 같으면 0입니다. 목표는 $C(x)$ 최대화입니다.

QAOA cost를 최소화하는 convention을 쓰려면

$$f(x)=-C(x)$$

로 둘 수 있습니다. 부호를 기록하지 않으면 optimizer가 가장 나쁜 cut을 찾았다고 오해할 수 있습니다.

## brute force 기준

```python
from itertools import product

edges = [(0, 1), (1, 2), (0, 2)]

def cut_value(bits: tuple[int, ...]) -> int:
    return sum(bits[i] != bits[j] for i, j in edges)

rows = []
for bits in product([0, 1], repeat=3):
    rows.append((bits, cut_value(bits)))

rows.sort(key=lambda item: item[1], reverse=True)
for row in rows:
    print(row)
```

triangle의 maximum cut은 2이고 bitwise complement 해가 같은 partition을 나타냅니다.

## penalty로 제약 넣기

제약 $g(x)=0$을 목적함수에

$$
\lambda g(x)^2
$$

로 추가할 수 있습니다. penalty가 너무 작으면 infeasible 해가 선택되고 너무 크면 energy scale과 optimizer landscape가 나빠질 수 있습니다. 제약이 사라지는 것이 아니라 목적함수에 비용으로 encode되는 것입니다.

## 과제

1. 4-node path MaxCut을 brute force합니다.
2. `정확히 하나 선택` 제약 $(x_0+x_1+x_2-1)^2$을 전개합니다.
3. penalty $\lambda=0.5,2,10$에서 최적해를 비교합니다.
4. Q matrix convention을 하나 정하고 bitstring 두 개를 matrix와 직접 식으로 모두 계산합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 최대화와 최소화 부호, Q의 대칭 convention, bitstring 변수 순서를 명시하지 않으면 서로 다른 식을 같은 문제라고 착각합니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
