## 기본 loop

```python
import numpy as np
from scipy.optimize import minimize

rng = np.random.default_rng(47)
initial = rng.uniform(0, np.pi, size=ansatz.num_parameters)

history = []

def callback(intermediate):
    # SciPy method/version에 따라 callback signature가 다를 수 있습니다.
    parameters = np.asarray(intermediate)
    value = cost_function(parameters)
    history.append({
        "iteration": len(history),
        "value": value,
        "parameters": parameters.copy(),
    })

result = minimize(
    cost_function,
    x0=initial,
    method="COBYLA",
    options={"maxiter": 100},
    callback=callback,
)
```

callback에서 비용을 다시 계산하면 evaluation budget이 늘어납니다. optimizer가 callback에 function value를 제공하는지 확인하거나 cost function 내부에서 history를 기록하는 방식을 고려합니다.

## 더 안전한 기록

```python
evaluation_history = []

def recorded_cost(parameters):
    value = cost_function(parameters)
    evaluation_history.append({
        "evaluation": len(evaluation_history),
        "value": value,
        "parameters": np.array(parameters, copy=True),
    })
    return value
```

iteration과 function evaluation은 다릅니다. optimizer 한 iteration에서 비용함수를 여러 번 호출할 수 있습니다.

## local exact와 hardware loop

로컬 exact Estimator에서는 cost가 deterministic할 수 있지만 hardware·finite shots에서는 noisy objective가 됩니다. noise가 있는 optimizer에는 shot budget, target precision, robust optimizer, session timeout이 추가로 중요합니다.

## 4. 예측 중심 통합 실험

### 실험 질문

동일한 p=1 목적함수에 여러 초기점과 optimizer 설정을 적용하고 매 평가의 parameters, energy, 시간, 오류를 history에 저장합니다.

### 실행 전에 적을 내용

1. 입력 상태 또는 입력 데이터의 크기와 순서를 적습니다.

2. 회로나 수식이 적용되는 순서를 한 단계씩 번호로 씁니다.

3. 정확히 예측할 수 있는 출력과 유한 샷 때문에 흔들릴 출력을 구분합니다.

4. 성공을 판정할 수치 또는 구조적 조건을 하나 정합니다.

5. 실패했을 때 가장 먼저 출력할 type, shape, mapping, version을 적습니다.

### 예상 결과

서로 다른 초기점은 다른 국소 지점에 도달할 수 있고 optimizer의 성공 플래그와 실제 최종 샘플 해 품질은 같은 개념이 아닙니다.

| 핵심 수치 |  |  |  |
| 회로 size·depth |  |  |  |

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 목적함수 호출마다 회로와 Hamiltonian을 다시 만들거나 평가 기록을 남기지 않으면 느린 원인과 부호·shape 오류를 재현할 수 없습니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
