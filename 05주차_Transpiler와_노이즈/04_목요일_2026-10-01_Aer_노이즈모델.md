# 5주차 목요일 - Aer 노이즈 모델

## 목표

- shot noise와 physical noise를 구분합니다.
- readout error와 depolarizing gate error를 모델링합니다.
- AerSimulator에 noise model을 연결합니다.
- noise model의 가정과 한계를 기록합니다.

## noise의 층

1. finite-shot sampling error: 이상적 확률에서도 발생
2. state preparation and measurement error
3. gate error: depolarization, coherent over-rotation 등
4. decoherence: T1 relaxation, T2 dephasing
5. crosstalk·drift·leakage: 단순 독립 모델보다 복잡

한 개 toy noise model이 실제 장치를 완전히 나타낸다고 생각하지 않습니다.

## Aer import

```python
from qiskit_aer import AerSimulator
from qiskit_aer.noise import NoiseModel, ReadoutError, depolarizing_error
```

구형 `from qiskit import Aer` 또는 `qiskit.providers.aer` 경로를 사용하지 않습니다.

## readout error

```python
noise_model = NoiseModel()

readout_error = ReadoutError([
    [0.95, 0.05],
    [0.10, 0.90],
])

noise_model.add_all_qubit_readout_error(readout_error)
```

행렬의 각 원소가 `실제 상태 → 보고된 결과` 중 어떤 조건부 확률인지 API 문서에서 확인합니다. 행 합이 1인지 검증합니다.

## depolarizing error

```python
one_qubit_error = depolarizing_error(0.002, 1)
two_qubit_error = depolarizing_error(0.02, 2)

noise_model.add_all_qubit_quantum_error(
    one_qubit_error,
    ["x", "sx", "rz"],
)
noise_model.add_all_qubit_quantum_error(
    two_qubit_error,
    ["cx"],
)
```

실제 simulator basis gate가 다르면 지정 instruction과 transpiled 회로가 일치해야 합니다.

## 실행

```python
from qiskit import transpile

simulator = AerSimulator(noise_model=noise_model)
isa = transpile(measured_circuit, simulator, seed_transpiler=9)
result = simulator.run(isa, shots=5000, seed_simulator=9).result()
counts = result.get_counts()
```

`seed_transpiler`와 `seed_simulator`는 다른 무작위성을 제어합니다.

## 실험

1. 결정적 $|0\rangle$, $|1\rangle$에서 readout confusion을 비교합니다.
2. Bell 상태에서 readout only와 gate+readout noise를 비교합니다.
3. CX 수를 인위적으로 늘린 회로에서 error 증가를 관찰합니다.
4. shots만 늘렸을 때 systematic bias가 사라지는지 확인합니다.

## 2. 핵심 유도와 손계산

### 수학·논리 전개

대칭 readout error는 실제 0을 1로, 실제 1을 0으로 기록할 확률을 조건부 행렬로 둡니다. depolarizing channel은 확률 p로 상태를 Pauli 오류 혼합 쪽으로 보내 gate가 만든 coherence와 correlation을 약화시킵니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

1. 출발하는 상태, 데이터, 변수 또는 가정을 먼저 씁니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

### 손으로 따라가는 예제

이상적 Bell 분포가 00과 11에 각 1/2일 때 독립 bit-flip readout error가 있으면 01과 10에도 질량이 생깁니다. gate depolarizing은 단지 라벨을 바꾸는 것이 아니라 Bell 상관과 여러 기저 기대값을 함께 낮춥니다.

Bell 회로에 readout error와 depolarizing error를 각각, 그리고 함께 적용하여 counts와 오류 지표 변화를 비교합니다.

### 실행 전에 적을 내용

4. 성공을 판정할 수치 또는 구조적 조건을 하나 정합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. NoiseModel에 instruction 이름이나 qubit 범위를 잘못 연결하거나 노이즈 없는 회로를 기준선 없이 보면 모델 효과를 해석할 수 없습니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
