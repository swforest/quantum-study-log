# 3주차 화요일 - Operator와 전역위상

## 목표

- 유니터리 회로를 `Operator`로 변환합니다.
- 행렬 곱과 circuit compose 순서를 검증합니다.
- `compose`, `tensor`, `expand`, `equiv`의 의미를 구분합니다.
- gate 동등성을 전역위상까지 고려해 판단합니다.

## Operator 기본

```python
from qiskit import QuantumCircuit
from qiskit.quantum_info import Operator

qc = QuantumCircuit(1)
qc.h(0)
qc.z(0)

operator = Operator(qc)
print(operator.data)
```

회로는 H 후 Z이므로 상태에 작용하는 전체 행렬은 $ZH$입니다. 코드 시간 순서와 행렬 표기의 곱 순서가 반대로 보이는 이유는 행렬이 ket의 왼쪽에서 작용하기 때문입니다.

## 동등성 실험

```python
from qiskit.circuit.library import XGate, YGate, ZGate

x = Operator(XGate())
y = Operator(YGate())
z = Operator(ZGate())

print(x.compose(y).data)
print(x.compose(y).equiv(1j * z))
```

Qiskit `compose`의 기본 순서를 문서와 작은 상태 실험으로 확인합니다. 이름만으로 추측하지 않습니다. 모호할 때는 $|0\rangle$과 $|1\rangle$에 각각 적용해 확인합니다.

## tensor와 expand

$A\otimes B$와 $B\otimes A$는 일반적으로 다릅니다.

```python
from qiskit.quantum_info import Operator

x_on_left = x.tensor(Operator.from_label("I"))
x_on_right = x.expand(Operator.from_label("I"))

print(x_on_left.data)
print(x_on_right.data)
```

메서드 이름보다 실제 basis label에 적용한 결과로 qubit 위치를 확인합니다.

## 회로가 Operator가 될 수 없는 경우

measurement, reset, 조건부 고전 제어가 들어간 전체 회로는 일반적으로 하나의 유니터리 행렬이 아닙니다.

```python
measured = QuantumCircuit(1, 1)
measured.h(0)
measured.measure(0, 0)
```

이 회로를 억지로 `Operator`로 바꾸기보다 측정 전 unitary 부분을 분리합니다.

## 전역위상

회로 객체에는 `global_phase`가 있을 수 있습니다. 두 회로의 행렬이 상수 위상만큼 달라도 상태의 물리적 예측은 같습니다. 하지만 controlled version을 만들 때 전역위상이 상대위상으로 드러날 수 있어 회로 조작 문맥에서는 함부로 버리지 않습니다.

## 과제

1. $HXH=Z$와 $HZH=X$를 `Operator.equiv`로 확인합니다.
2. $R_x(\pi)$와 X의 전역위상 관계를 계산합니다.
3. SWAP과 CX 세 개 분해를 Operator로 비교합니다.
4. 임의 2×2 행렬을 넣고 `is_unitary_matrix` 또는 $U^\dagger U$로 유니터리 여부를 검증합니다.

## 2. 핵심 유도와 손계산

### 수학·논리 전개

연속 게이트 U 뒤에 V를 적용한 전체 연산은 VU이며 상태 열벡터 오른쪽에서 U가 먼저 작용합니다. 유니터리 검사는 U dagger U=I이고, 두 연산자 A와 exp(i phi)A는 원소가 달라도 물리적으로 동등합니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

1. 출발하는 상태, 데이터, 변수 또는 가정을 먼저 씁니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

### 손으로 따라가는 예제

H 뒤에 Z를 적용한 회로와 ZH 행렬을 0에 적용하면 minus 상태가 됩니다. 반대로 HZ를 0에 적용하면 Z가 0을 그대로 두므로 plus 상태가 되어 곱 순서가 실제 출력으로 구분됩니다.

오늘 가장 가능성 높은 실패는 다음과 같습니다. 행렬 곱의 오른쪽 연산이 먼저 적용된다는 점이나 tensor factor의 큐비트 배치를 놓치면 회로와 행렬 결과가 뒤바뀝니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
