## backend 선택

```python
from qiskit_ibm_runtime import QiskitRuntimeService

service = QiskitRuntimeService()
backend = service.least_busy(
    operational=True,
    simulator=False,
    min_num_qubits=3,
)
```

`least_busy`는 회로 품질 최적 backend와 동일한 뜻이 아닙니다. queue, qubit 수, target, calibration, plan access를 함께 봅니다.

## ISA 회로

```python
from qiskit.transpiler.preset_passmanagers import generate_preset_pass_manager

pm = generate_preset_pass_manager(
    backend=backend,
    optimization_level=1,
    seed_transpiler=43,
)
isa_circuit = pm.run(measured_circuit)
```

Runtime primitive에 추상 회로를 그대로 넘겨 provider가 알아서 처리할 것이라고 가정하지 않습니다.

## 제출 골격

다음 코드는 사용자의 실제 제출 승인이 있을 때만 실행합니다.

```python
from qiskit_ibm_runtime import SamplerV2

sampler = SamplerV2(mode=backend)
job = sampler.run([isa_circuit], shots=1024)

print(job.job_id())
print(job.status())

result = job.result()
counts = result[0].data.meas.get_counts()
```

register 이름이 다르면 `meas`도 달라집니다.

로컬 또는 fake backend에서 제출 직전 파이프라인을 리허설하고 실제 Runtime 코드는 제출 줄을 분리해 job id와 메타데이터 기록 양식을 만듭니다.

### 실행 전에 적을 내용

1. 입력 상태 또는 입력 데이터의 크기와 순서를 적습니다.

2. 회로나 수식이 적용되는 순서를 한 단계씩 번호로 씁니다.

3. 정확히 예측할 수 있는 출력과 유한 샷 때문에 흔들릴 출력을 구분합니다.

4. 성공을 판정할 수치 또는 구조적 조건을 하나 정합니다.

5. 실패했을 때 가장 먼저 출력할 type, shape, mapping, version을 적습니다.

2. 먼저 type과 shape가 예측과 같은지 확인합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 토큰을 코드에 넣거나 원본 추상 회로를 그대로 제출하거나 사용자 확인 없이 실제 QPU job을 실행하면 보안·비용·실행 오류가 발생합니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
