# 6주차 화요일 - StatevectorSampler

## 목표

- 로컬 V2 Sampler로 회로를 샘플링합니다.
- parameterized PUB를 실행합니다.
- BitArray에서 counts·bitstrings를 추출합니다.
- register 이름과 shot axis를 올바르게 해석합니다.

## 기본 실행

```python
from qiskit import QuantumCircuit
from qiskit.primitives import StatevectorSampler

bell = QuantumCircuit(2)
bell.h(0)
bell.cx(0, 1)
bell.measure_all()

sampler = StatevectorSampler(default_shots=1024, seed=41)
job = sampler.run([bell])
result = job.result()

pub_result = result[0]
bit_array = pub_result.data.meas

print(bit_array.get_counts())
print(bit_array.get_bitstrings()[:10])
```

`StatevectorSampler`는 ideal statevector 기반 reference sampler입니다. device noise를 자동 모델링하지 않습니다.

## register 이름

```python
from qiskit import ClassicalRegister, QuantumRegister

q = QuantumRegister(2, "q")
answer = ClassicalRegister(2, "answer")
qc = QuantumCircuit(q, answer)
qc.x(q[0])
qc.measure(q, answer)
```

결과는 `data.answer`에 들어갑니다. `data.meas`를 무조건 사용하지 않습니다.

## parameterized PUB

```python
import numpy as np
from qiskit.circuit import Parameter

theta = Parameter("theta")
qc = QuantumCircuit(1)
qc.ry(theta, 0)
qc.measure_all()

values = np.array([
    [0.0],
    [np.pi / 2],
    [np.pi],
])

job = sampler.run([(qc, values, 2000)])
result = job.result()[0]
```

parameter array shape와 결과 leading shape를 출력해 확인합니다. 수업 버전의 공식 예제와 다르면 signature를 맞춥니다.

## shots와 seed

- default shots: primitive 생성 시 기본값
- PUB shots: 특정 PUB에서 override 가능
- seed: 로컬 샘플 재현성을 돕지만 모든 provider·hardware 결과를 결정하지 않음

샷 수를 늘리면 sampling variance가 줄지만 ideal sampler를 noise simulator로 바꾸지는 않습니다.

## 과제

1. Ry sweep의 $P(1)=\sin^2(\theta/2)$와 sampled frequency를 비교합니다.
2. 두 classical register가 있는 회로에서 DataBin field를 확인합니다.
3. `get_bitstrings`, `get_counts`, shot 수 합계를 검증합니다.
4. seed를 같게·다르게 실행해 결과 재현성을 비교합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. 측정이 없는 회로를 넣거나 data.meas를 모든 회로에 고정해 쓰면 빈 결과 또는 존재하지 않는 필드 접근 문제가 생깁니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
