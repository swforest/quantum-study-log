## 어떤 Primitive를 선택하는가

### Sampler

질문: `측정하면 어떤 bitstring들이 얼마나 나오는가?`

- 회로에 measurement 필요
- 회로·parameter values·shots를 입력
- shot-level bit data 또는 counts를 해석
- dynamic circuit의 classical register 구조를 보존

### Estimator

질문: `상태에서 특정 observable의 기대값은 얼마인가?`

- 일반적으로 회로에 measurement를 직접 넣지 않음
- 회로·observable·parameter values·precision을 입력
- expectation values와 표준오차·metadata 해석

## PUB

PUB는 한 회로와 그 회로에 broadcast되는 데이터를 묶는 작업 단위입니다.

Sampler PUB 개념형:

```text
(circuit, parameter_values, optional_shots)
```

Estimator PUB 개념형:

```text
(circuit, observables, parameter_values, optional_precision)
```

정확한 허용 shape는 현재 API 문서를 확인합니다. 중요한 점은 V2가 회로 목록과 observable 목록을 별도 positional list로 받던 V1 구조와 다르다는 것입니다.

## 결과 계층

```text
PrimitiveResult
└─ result[pub_index]: PubResult
   ├─ data: DataBin
   │  ├─ meas 또는 classical-register-name: BitArray  (Sampler)
   │  └─ evs, stds 등                              (Estimator)
   └─ metadata
```

코드에서 `result.get_counts()`라고 바로 추측하지 않고 한 단계씩 type과 field를 확인합니다.

```python
print(type(result))
print(type(result[0]))
print(result[0].data)
print(result[0].metadata)
```

## V1 감지표

다음이 보이면 구형 예제일 가능성이 큽니다.

- `from qiskit.primitives import Sampler, Estimator`
- `sampler.run(circuits=[...])`
- `result.quasi_dists`
- `result.values`
- Runtime `Sampler(session=...)` without V2 naming
- circuit와 observable를 PUB tuple이 아닌 별도 list로 전달

## 2. 핵심 유도와 손계산

### 수학·논리 전개

Sampler PUB는 최대 (circuit, parameter_values, shots), Estimator PUB는 최대 (circuit, observables, parameter_values, precision)의 구조를 가집니다. 여러 배열은 broadcasting 규칙으로 결합되고 각 PUB는 결과의 같은 인덱스 PubResult에 대응합니다.

이 문장을 그대로 암기하지 말고 다음 순서로 다시 전개합니다.

1. 출발하는 상태, 데이터, 변수 또는 가정을 먼저 씁니다.

2. 적용되는 게이트, 행렬, 치환, API 변환을 한 단계씩 분리합니다.

3. 단계마다 보존되어야 하는 정규화, 차원, type, shape, mapping을 확인합니다.

4. 마지막 식이나 객체가 오늘 중심 질문에 어떤 답을 주는지 한 문장으로 연결합니다.

5. 부호, 순서, 인덱스 가운데 하나를 바꾸었을 때 결과가 어떻게 달라지는지 반례를 만듭니다.

### 손으로 따라가는 예제

측정 Bell 회로 하나를 Sampler에 넣으면 result[0].data 아래 register 이름의 BitArray가 생깁니다. 측정 없는 RY 회로와 Z observable을 Estimator에 넣으면 result[0].data.evs에서 기대값을 읽습니다.

#### 예제 재현 절차

- 첫 번째 시도에서는 코드를 실행하지 않습니다.
- 입력과 가능한 출력 후보를 종이에 적습니다.
- 중간 상태 또는 중간 값을 최소 두 단계 기록합니다.
- 마지막에만 기존 본문의 코드와 비교합니다.
- 값이 다르면 정답을 고치기 전에 convention과 순서를 먼저 확인합니다.

### 출력 해석 기준

결과를 type(result), type(result[0]), result[0].data, data.keys 순서로 탐색합니다. V1의 quasi_dists 또는 values가 없다는 사실을 오류가 아니라 V2 결과 모델의 변화로 해석합니다.

- 배열의 각 축과 문자열의 각 비트가 무엇을 뜻하는지 표시합니다.
- 회로 구조가 맞다는 증거와 물리적 결과가 맞다는 증거를 분리합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. V1의 quasi_dists나 values 속성을 기대하거나 parameter 및 observable broadcasting shape를 확인하지 않으면 결과를 잘못 접근합니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
- 독립적인 손계산 또는 brute-force 기준선과 비교합니다.
- 남은 차이를 모델 오류, 구현 오류, 통계 변동으로 분류합니다.
