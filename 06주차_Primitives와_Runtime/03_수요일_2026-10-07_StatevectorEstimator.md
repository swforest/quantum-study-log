# 6주차 수요일 - StatevectorEstimator

## 목표

- local Estimator V2로 기대값을 계산합니다.
- circuit·observable·parameter values를 PUB로 묶습니다.
- observable array와 parameter sweep broadcast를 이해합니다.
- exact result와 finite precision·hardware result를 구분합니다.

## 기본 예

```python
from qiskit import QuantumCircuit
from qiskit.primitives import StatevectorEstimator
from qiskit.quantum_info import SparsePauliOp

qc = QuantumCircuit(1)
qc.h(0)

observables = [
    SparsePauliOp.from_list([("X", 1.0)]),
    SparsePauliOp.from_list([("Z", 1.0)]),
]

estimator = StatevectorEstimator()
job = estimator.run([(qc, observables)])
result = job.result()[0]

print(result.data.evs)
print(result.data.stds)
print(result.metadata)
```

예상 기대값은 X=1, Z=0입니다.

## parameter sweep

```python
import numpy as np
from qiskit.circuit import Parameter

theta = Parameter("theta")
ansatz = QuantumCircuit(1)
ansatz.ry(theta, 0)

z = SparsePauliOp.from_list([("Z", 1.0)])
values = np.array([[0.0], [np.pi / 2], [np.pi]])

job = estimator.run([(ansatz, z, values)])
evs = job.result()[0].data.evs
print(evs)
```

이론값은 $\langle Z\rangle=\cos\theta$입니다.

## observable의 qubit 순서

다중 qubit `SparsePauliOp` label은 little-endian mapping을 확인해야 합니다. q0만 $|1\rangle$인 비대칭 상태에서 `ZI`, `IZ` 기대값을 비교해 label 방향을 검증합니다.

## expectation과 shots

StatevectorEstimator의 기본 동작은 exact statevector 계산에 가깝지만 implementation option에 따라 precision·randomness가 관련될 수 있습니다. Runtime Estimator는 실제 측정·오류·target precision에 따른 결과를 줍니다. 클래스 이름이 Estimator라는 이유로 모든 구현의 통계 특성이 같다고 생각하지 않습니다.

## 과제

1. Bell 상태에서 `ZZ`, `XX`, `YY`, `ZI` 기대값을 계산합니다.
2. parameter sweep 결과를 수식 곡선과 비교합니다.
3. observable 여러 개와 parameter 여러 세트의 결과 shape를 그립니다.
4. Hamiltonian $0.5ZI+0.5IZ+1.2XX$의 기대값을 항별 합과 전체 연산으로 비교합니다.

## 7. 실패 진단 절차

오늘 가장 가능성 높은 실패는 다음과 같습니다. observable 문자열의 큐비트 순서, parameter 배열 마지막 축, 회로의 measurement 유무를 잘못 다루면 값 또는 shape가 어긋납니다.

### 1단계: 환경

- Python, Qiskit, 선택 패키지 버전을 출력합니다.
- 노트북 kernel과 패키지를 설치한 interpreter가 같은지 확인합니다.
- 구형 예제의 import와 현재 API를 이름만 바꾸지 말고 목적별로 매핑합니다.

### 2단계: 입력

- qubit 수, classical bit 수, parameter 수를 적습니다.
- 배열 shape와 axis 의미를 적습니다.
- bitstring과 Pauli 문자열의 변수 순서를 적습니다.

### 3단계: 변환

- 회로 instruction 순서와 compose 순서를 확인합니다.
- transpilation이 있다면 원본과 ISA 회로를 분리합니다.
- layout, register mapping, parameter binding을 출력합니다.

### 4단계: 출력

- result 객체를 추측하지 않고 type, 첫 PUB, data, key 순서로 내려갑니다.
- 정확값, 기대값, 샷 counts 가운데 지금 얻은 결과의 종류를 적습니다.
- 값이 아니라 shape부터 예측과 비교합니다.

### 5단계: 의미

- 코드가 성공했다는 사실만으로 물리적·수학적 정답이라고 결론 내리지 않습니다.
